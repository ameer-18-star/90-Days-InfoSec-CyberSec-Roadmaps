90-Day Roadmap For "Cloud Security Analyst" Mastery

An intermediate-track plan for learners who already know basic networking, Linux, and one cloud provider at a beginner level — and are ready to specialize in securing cloud infrastructure, identity, containers, and workloads at scale.

Phase 1: Cloud Security Fundamentals & IAM

Days 1-30: Shared responsibility, identity & access management, networking, and your first cloud lab account

🎯 Phase 1 Goals

Shared Responsibility Model IAM VPC/Network Security Storage Security Logging & Monitoring

Week 1: Cloud Security Foundations

  • Study the shared responsibility model in depth across AWS, Azure, and GCP
  • Set up a free-tier AWS account with billing alerts and root account MFA enabled
  • Learn the AWS Well-Architected Framework's Security Pillar at a high level
  • Study how cloud security differs from on-prem: ephemeral resources, API-driven everything, shared infra
  • Learn the basics of cloud regions, availability zones, and how they affect security/compliance
  • Install and configure the AWS CLI and AWS CloudShell for hands-on practice
  • Read through one real-world cloud breach case study (e.g. Capital One S3/IAM breach) and map root cause
  • Document 15 cloud security terms in your own glossary (CSPM, IAM, KMS, VPC, etc.)
AWS Free Tier Shared Responsibility AWS CLI Well-Architected

Task heading at the end of week: Cloud Breach Case Study

Write a one-page breakdown of a real cloud security incident: what misconfiguration enabled it, what control would have prevented it, and your glossary of 15 terms.

Week 2: Identity & Access Management (IAM) Deep Dive

  • Study IAM users, groups, roles, and policies in AWS — and how Azure AD/Entra ID and GCP IAM compare conceptually
  • Learn the principle of least privilege and how to apply it to IAM policy writing
  • Practice writing custom IAM policies (JSON) instead of relying only on managed policies
  • Study IAM privilege escalation paths: common misconfigurations attackers chase
  • Learn cross-account roles, assume-role workflows, and federation basics (SAML/OIDC)
  • Practice using the IAM Policy Simulator to test policy effects before applying
  • Study service control policies (SCPs) in AWS Organizations as guardrails
  • Learn MFA enforcement, access key rotation, and credential lifecycle management
IAM Policies Least Privilege SCPs Federation

Task heading at the end of week: Least-Privilege IAM Policy Set

Write 3 custom IAM policies from scratch for a fictional 3-tier app (read-only analyst, deploy role, admin role), then test each with the Policy Simulator.

Week 3: Network Security in the Cloud

  • Study VPC architecture: subnets, route tables, internet/NAT gateways, peering
  • Learn security groups vs. network ACLs — stateful vs. stateless filtering
  • Practice building a segmented VPC (public/private subnets) with proper routing
  • Study VPC endpoints and PrivateLink as ways to avoid public internet exposure
  • Learn how cloud load balancers and WAFs (AWS WAF) fit into the security architecture
  • Study DDoS protection basics (AWS Shield) and when it matters
  • Practice flow log analysis: enable VPC Flow Logs and identify suspicious traffic patterns
  • Learn bastion host vs. Session Manager / SSM as secure access patterns
VPC Security Groups AWS WAF Flow Logs

Task heading at the end of week: Segmented VPC Build

Build a VPC with public/private subnets, correct security group rules, and VPC Flow Logs enabled; document your architecture with a diagram.

Week 4: Storage, Encryption & Logging Fundamentals

  • Study S3 bucket security: public access blocks, bucket policies, ACLs, versioning
  • Learn encryption at rest (KMS, SSE-S3, SSE-KMS) and encryption in transit basics
  • Practice setting up a KMS customer-managed key and applying it to an S3 bucket
  • Study how key rotation and key policies affect access control separately from IAM
  • Learn CloudTrail fundamentals: what it logs, how to enable org-wide trails, log integrity validation
  • Study CloudWatch alarms and metrics for security-relevant events
  • Practice configuring a CloudTrail trail with S3 log storage and basic alerting on root account usage
  • Document common storage misconfigurations and a personal checklist to catch them
S3 Security KMS CloudTrail CloudWatch

Task heading at the end of week: Storage & Logging Baseline

Configure a KMS-encrypted, public-access-blocked S3 bucket plus an org-wide CloudTrail trail with a CloudWatch alarm for root account login.

🎯 Milestone 1 Achievement

You can configure least-privilege IAM, build a properly segmented VPC, secure storage with encryption, and set up logging/monitoring baselines — the foundational toolkit of a Cloud Security Analyst.

Phase 2: CSPM, Container Security & Multi-Cloud Awareness

Days 31-60: Move from manual configuration into automated posture management, container/Kubernetes security, and cross-cloud concepts

🎯 Phase 2 Goals

CSPM Tooling Container & K8s Security IaC Security Secrets Management Multi-Cloud Basics

Week 5: Cloud Security Posture Management (CSPM)

  • Learn what CSPM tools actually do: continuous configuration drift detection against benchmarks
  • Set up and run Prowler against your free-tier AWS account, triaging real findings
  • Practice running ScoutSuite for a broader multi-service security audit
  • Study the CIS AWS Foundations Benchmark and map findings to specific controls
  • Learn how AWS Security Hub and AWS Config aggregate and continuously monitor compliance
  • Practice writing a remediation plan from CSPM output, prioritized by severity
  • Study how commercial CSPM platforms (Wiz, Orca, Prisma Cloud) extend beyond open-source tools
  • Document false-positive triage logic so you don't waste remediation effort on non-issues
Prowler ScoutSuite CIS Benchmarks AWS Security Hub

Task heading at the end of week: CSPM Findings Report

Run Prowler + ScoutSuite against your lab account, triage the top 15 findings, and produce a prioritized remediation report mapped to CIS Benchmark control IDs.

Week 6: Infrastructure-as-Code (IaC) Security

  • Study why IaC scanning matters: catching misconfigurations before they're ever deployed
  • Set up Checkov and tfsec to scan a sample Terraform configuration
  • Practice fixing common Terraform security findings: open security groups, unencrypted resources, public S3
  • Learn how to integrate IaC scanning into a CI/CD pipeline (GitHub Actions) as a pre-deploy gate
  • Study CloudFormation security scanning basics (cfn-lint, cfn-nag) for AWS-native IaC
  • Learn policy-as-code concepts using Open Policy Agent (OPA) / Sentinel at a conceptual level
  • Practice writing a custom Checkov rule for an organization-specific requirement
  • Build a personal "IaC security checklist" for reviewing any new Terraform module
Checkov tfsec Terraform OPA

Task heading at the end of week: IaC Security Pipeline

Take a deliberately insecure Terraform module, scan it, fix every finding, and wire Checkov into a GitHub Actions workflow as a deploy gate.

Week 7: Container & Kubernetes Security

  • Study container security fundamentals: image layers, base image risk, privileged containers
  • Practice scanning container images with Trivy and Grype for known CVEs
  • Learn Dockerfile hardening best practices (non-root users, minimal images, multi-stage builds)
  • Study Kubernetes architecture security basics: control plane, etcd, kubelet exposure risks
  • Learn Kubernetes RBAC: roles, role bindings, and least-privilege service accounts
  • Study network policies for pod-to-pod traffic restriction in Kubernetes
  • Practice running kube-bench against a sample cluster (or managed EKS) for CIS Kubernetes Benchmark checks
  • Learn pod security standards (restricted/baseline/privileged) and admission controllers
Trivy Kubernetes RBAC kube-bench Network Policies

Task heading at the end of week: Hardened K8s Namespace

Build a Kubernetes namespace with least-privilege RBAC, network policies restricting pod traffic, and Trivy-scanned hardened container images.

Week 8: Secrets Management & Multi-Cloud Concepts

  • Learn why hardcoded secrets are a top cloud breach cause and how secrets sprawl happens
  • Set up AWS Secrets Manager or HashiCorp Vault and migrate a hardcoded credential into it
  • Practice scanning a repo with gitleaks/trufflehog for leaked secrets in commit history
  • Study secret rotation strategies and how applications should retrieve secrets at runtime
  • Learn the basic security model differences between AWS, Azure, and GCP (IAM naming, network constructs)
  • Study cloud metadata service abuse (IMDSv1 vs IMDSv2) and how to enforce the safer version
  • Practice a cross-cloud terminology mapping exercise (e.g. AWS IAM Role ≈ Azure Managed Identity ≈ GCP Service Account)
  • Document your own "multi-cloud Rosetta Stone" cheat sheet for quick reference
Secrets Manager/Vault gitleaks IMDSv2 Multi-Cloud IAM

Task heading at the end of week: Secrets Migration & Cheat Sheet

Migrate 3 hardcoded credentials into AWS Secrets Manager with runtime retrieval code, plus a one-page multi-cloud terminology cheat sheet.

🚀 Milestone 2 Achievement

You can run CSPM tooling, scan and secure IaC before deployment, harden containers and Kubernetes clusters, and manage secrets properly — the practical toolkit that fills a Cloud Security Analyst's day-to-day work.

Phase 3: Incident Response, Automation & Career Readiness

Days 61-90: Cloud-native incident response, security automation, and the certification/interview push

🎯 Phase 3 Goals

Cloud Incident Response SOAR/Automation Zero Trust Concepts Compliance in Cloud Interview Prep

Week 9: Cloud Incident Response

  • Study the cloud incident response lifecycle: detection, containment, eradication, recovery, lessons learned
  • Learn how to isolate a compromised EC2 instance (security group quarantine, snapshot for forensics)
  • Practice a tabletop exercise: a leaked IAM access key scenario, and the exact response steps
  • Study how to use GuardDuty findings to drive an investigation workflow
  • Learn cloud forensics basics: preserving EBS snapshots, memory capture limitations in cloud
  • Practice writing an incident timeline reconstruction using CloudTrail + GuardDuty + VPC Flow Logs together
  • Study key rotation and credential revocation as immediate containment actions
  • Write a one-page cloud incident response runbook for a "leaked access key" scenario
GuardDuty Incident Response Forensic Snapshots Containment

Task heading at the end of week: Leaked Key IR Runbook

Write a complete incident response runbook for a leaked AWS access key, covering detection, containment, eradication, and a CloudTrail-based timeline reconstruction.

Week 10: Security Automation & SOAR Concepts

  • Learn how Lambda functions can auto-remediate common findings (e.g. auto-revoke a public S3 bucket)
  • Practice writing a simple Lambda function triggered by a GuardDuty/Security Hub finding
  • Study EventBridge rules for routing security events to automated response workflows
  • Learn SOAR (Security Orchestration, Automation and Response) concepts at a platform-agnostic level
  • Practice building an automated Slack/email alert pipeline for high-severity CSPM findings
  • Study how auto-remediation guardrails prevent automation from causing its own outages
  • Learn the basics of Zero Trust architecture as it applies to cloud-native environments
  • Document a personal "automation candidates" list from your Phase 1-2 manual remediation work
Lambda Auto-Remediation EventBridge SOAR Concepts Zero Trust

Task heading at the end of week: Auto-Remediation Lambda

Build a Lambda function triggered by a Security Hub finding that automatically blocks public access on a misconfigured S3 bucket, with logging of the action taken.

Week 11: Cloud Compliance & Professional Reporting

  • Study how compliance frameworks (PCI-DSS, HIPAA, SOC 2) map to cloud-specific controls
  • Learn AWS Artifact and how cloud providers supply their own compliance attestations
  • Practice mapping CIS Benchmark findings to a relevant compliance framework for a client-style report
  • Study how to write a cloud security assessment report: scope, methodology, findings, remediation
  • Learn CVSS scoring as applied to cloud misconfigurations (not just code vulnerabilities)
  • Practice presenting a cloud risk finding to a "non-technical stakeholder" in plain language
  • Study cost-of-breach context (e.g. industry breach cost reports) to frame business impact in reports
  • Compile your 90-day labs into a single portfolio-style master cloud security report
AWS Artifact Compliance Mapping CVSS Report Writing

Task heading at the end of week: Master Cloud Security Report

Compile your strongest 5 findings across all 90 days into one polished report, including compliance framework mapping and CVSS-scored severity.

Week 12: Certification & Interview Readiness

  • Review and attempt practice questions aligned to a target cert (e.g. AWS Security Specialty, CCSK, or Security+)
  • Do a full mock cloud security assessment under time pressure on a fresh sandbox account, then report within 4 hours
  • Prepare answers for common cloud security interview questions (explain shared responsibility, walk through IAM policy design, etc.)
  • Build a one-page resume bullet list translating your 90 days into measurable skills/achievements
  • Polish your GitHub: pin your best 3 projects (security pipeline, K8s baseline, IR runbook) with clean READMEs
  • Practice a mock technical interview (explain a cloud breach chain end-to-end out loud)
  • Research target companies/industries and tailor your resume + LinkedIn headline accordingly
  • Plan your next 90 days: pick a specialization (Kubernetes security, cloud IR, or DevSecOps engineering)
Mock Interviews Resume Building GitHub Portfolio Cert Prep

Task heading at the end of week: Job-Ready Cloud Security Portfolio

Finalize a GitHub portfolio, resume bullets, and one polished cloud security assessment report — your complete application package for Cloud Security Analyst roles.

🏆 Final Achievement

Congratulations! You now have a working cloud security toolkit (IAM, network security, CSPM, IaC scanning, container/K8s security, incident response, automation) plus a portfolio of real reports and a job-ready application package — the foundation of a genuinely employable Cloud Security Analyst.

What Next

Where to take your cloud security career after Day 90

1. Specialize

  • Pick one lane: cloud architecture security, Kubernetes/container security, or cloud incident response
  • Go deep on a second cloud provider (Azure or GCP) to become genuinely multi-cloud
  • Consider DevSecOps engineering as a hybrid automation-focused role
  • Explore cloud forensics and incident response as a specialized track
  • Look into security architecture/landing zone design as a senior path
  • Consider a CSPM/SOAR platform specialization (Wiz, Orca, Prisma Cloud)
  • Specialize in compliance-heavy industries (finance, healthcare) in the cloud
  • Pursue an advanced cert aligned to your chosen lane
  • Join a specialized community for that niche
  • Set a 6-month deep-specialization goal

2. Apply & Network

  • Apply to entry-level Cloud Security Analyst / Cloud Security Engineer roles weekly
  • Tailor your resume per job description using your portfolio reports
  • Attend local Cloud Security Alliance/AWS user group meetups
  • Reach out to cloud security professionals on LinkedIn for informational chats
  • Ask for referrals once you've built real community connections
  • Keep your GitHub portfolio updated with new projects
  • Practice mock interviews monthly to stay sharp
  • Track applications and follow up professionally
  • Consider freelance/contract cloud security audits to build experience
  • Set a weekly application/networking quota and stick to it

3. Keep Building

  • Stay current with weekly cloud security advisories and CVE roundups
  • Do at least one cloud CTF (flAWS, CloudGoat) or lab per week to stay sharp
  • Re-test old projects with new tools/techniques quarterly
  • Write a monthly technical blog post about something you learned
  • Build a second, more advanced portfolio project every 90 days
  • Track new cloud-native security service releases (AWS re:Inforce announcements, etc.)
  • Mentor beginners — teaching reinforces your own mastery
  • Read one new cloud security book per month
  • Attend at least one virtual conference talk per month
  • Reassess your roadmap every quarter and adjust goals

4. Give Back

  • Turn your 90-day notes into content for Virtual Mentors SOIT
  • Create a beginner-friendly cloud security series for your audience
  • Answer questions in community forums/Discords regularly
  • Open-source one of your lab setups or remediation scripts for others to use
  • Host a free workshop/webinar on one cloud security topic
  • Write a "lessons learned" retrospective on your 90 days publicly
  • Pair up with another learner for accountability
  • Contribute documentation fixes to a tool you use often
  • Review and give feedback on a peer's cloud security assessment
  • Pay it forward — share this exact roadmap with someone starting out

Stay curious, document everything, and keep auditing what you build.
