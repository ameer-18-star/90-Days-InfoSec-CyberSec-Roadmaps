90-Day Roadmap For "Application Security Analyst" Mastery

An intermediate-track plan for learners who already know basic networking, Linux, and one programming language — and are ready to specialize in finding, exploiting, and fixing vulnerabilities inside real applications.

Phase 1: AppSec Fundamentals & Manual Testing

Days 1-30: Secure SDLC, OWASP Top 10, manual exploitation, and your first vulnerable-app lab

🎯 Phase 1 Goals

OWASP Top 10 Burp Suite HTTP/HTTPS Internals Secure SDLC Manual Exploitation

Week 1: Web & HTTP Internals Refresher

  • Map the full HTTP request/response lifecycle: methods, headers, status codes, cookies, sessions
  • Study TLS handshake basics and why HTTPS misconfigurations matter for AppSec
  • Install and configure Burp Suite Community: proxy, repeater, intruder, decoder
  • Set up FoxyProxy + Burp CA cert to intercept your own browser traffic
  • Walk through DVWA (Damn Vulnerable Web App) setup in Docker
  • Review same-origin policy, CORS, and cookie attributes (HttpOnly, Secure, SameSite)
  • Read the OWASP Top 10 (2021) list end-to-end once, just for orientation
  • Document 10 HTTP headers and their security relevance in your own notes
Burp Suite DVWA Docker OWASP

Task heading at the end of week: HTTP Traffic Map

Intercept and document 15 different requests from a real site (with permission/on your own test app) in Burp, annotating each header and why it exists.

Week 2: Injection Vulnerabilities

  • Deep dive SQL injection: in-band, blind (boolean & time-based), and out-of-band
  • Practice manual SQLi on DVWA and PortSwigger Web Security Academy labs
  • Learn parameterized queries / prepared statements as the core fix
  • Study command injection and how OS-level shell calls get abused
  • Explore NoSQL injection differences (MongoDB operator injection)
  • Practice with sqlmap but focus on understanding what it automates, not just running it
  • Learn how WAFs detect/block injection and common bypass techniques (for understanding, not evasion abuse)
  • Write remediation notes: input validation vs. output encoding vs. parameterization
SQLi sqlmap PortSwigger Academy NoSQL

Task heading at the end of week: Injection Lab Writeup

Complete 8 PortSwigger SQLi labs and write a one-page report per lab: vulnerability, exploitation steps, root cause, and fix.

Week 3: XSS, CSRF & Client-Side Attacks

  • Master reflected, stored, and DOM-based XSS with hands-on labs
  • Learn Content Security Policy (CSP) as a primary XSS mitigation
  • Study CSRF mechanics, anti-CSRF tokens, and SameSite cookie defenses
  • Explore clickjacking and frame-busting / X-Frame-Options / CSP frame-ancestors
  • Learn open redirect vulnerabilities and real-world phishing chains using them
  • Practice bypassing weak input filters/sanitizers in controlled labs
  • Study postMessage vulnerabilities and insecure cross-origin communication
  • Build a personal cheat sheet of XSS payload patterns and corresponding fixes
XSS CSRF CSP Clickjacking

Task heading at the end of week: Client-Side Attack Chain

Build a small vulnerable Flask/Node app with stored XSS + CSRF, exploit it yourself, then patch both flaws and document the before/after code.

Week 4: Auth, Session & Access Control Flaws

  • Study broken authentication patterns: weak password policy, credential stuffing exposure
  • Practice session fixation and session hijacking scenarios in a lab
  • Deep dive IDOR (Insecure Direct Object Reference) and horizontal/vertical privilege escalation
  • Learn JWT structure, signature verification flaws, and "alg:none" style attacks
  • Study OAuth2/OIDC flow basics and common misconfigurations
  • Practice multi-step access-control testing methodology (map roles, test boundaries)
  • Learn rate limiting and brute-force protection mechanisms
  • Complete OWASP Top 10 categories A01 (Broken Access Control) and A07 (Auth Failures) labs
JWT IDOR OAuth2 Session Mgmt

Task heading at the end of week: Access Control Audit

On a lab app with 3 user roles, manually map every endpoint's intended permissions, then test and document every boundary that can be bypassed.

🎯 Milestone 1 Achievement

You can manually identify, exploit, and explain the root cause of 6 of the OWASP Top 10 categories on a live vulnerable application — and write a clear, client-ready vulnerability report for each.

Projects After Phase 1

Pick one to consolidate manual testing skills before moving into tooling and automation.

Vulnerable App Pentest Report

Fully test OWASP Juice Shop manually and produce a professional pentest report covering 10+ findings.

Hint: Use a standard report template (executive summary, findings table, CVSS-style severity, remediation).

JWT Auth Bypass Lab

Build a small API with intentionally weak JWT validation, then break it 3 different ways.

Hint: Try alg confusion, weak secret brute-forcing, and missing expiry checks.

Burp Macro & Session Handling

Configure Burp macros and session handling rules to automate authenticated scanning of a multi-step login app.

Hint: Use Project Options > Sessions in Burp to handle CSRF tokens automatically.

OWASP Top 10 Teaching Carousel

Turn your Phase 1 notes into a 10-part educational explainer series for your audience.

Hint: One vulnerability per piece, attacker view + defender fix, beginner-friendly language.

Phase 2: Secure Code Review, SAST/DAST & API Security

Days 31-60: Move from manual hacking into tool-assisted analysis, secure coding, and API/cloud-aware AppSec

🎯 Phase 2 Goals

SAST/DAST Secure Code Review API Security Threat Modeling SSRF/Deserialization

Week 5: SAST Tooling & Secure Code Review

  • Learn the difference between SAST, DAST, IAST, and SCA conceptually
  • Set up Semgrep and write custom rules to catch insecure patterns in code
  • Practice manual secure code review on intentionally vulnerable repos (e.g. OWASP NodeGoat, WebGoat)
  • Study common insecure coding patterns: hardcoded secrets, insecure deserialization, eval() misuse
  • Run SonarQube Community locally and triage findings (true positive vs false positive)
  • Learn dependency scanning with OWASP Dependency-Check / npm audit / pip-audit
  • Study CWE classification and how it maps to OWASP Top 10
  • Practice writing a finding with CWE ID, CVSS score, and remediation snippet
Semgrep SonarQube CWE/CVSS SCA

Task heading at the end of week: Code Review Report

Run Semgrep + SonarQube on OWASP NodeGoat, triage all results, and produce a findings report with CWE/CVSS tagging for the top 10 real issues.

Week 6: DAST & Automated Scanning

  • Set up OWASP ZAP and run full active + passive scans against a lab target
  • Configure Burp Suite's scanner (or ZAP automation framework) for authenticated scans
  • Learn how to reduce false positives through scan context and scope tuning
  • Study SSRF (Server-Side Request Forgery): internal network pivoting, cloud metadata abuse
  • Practice SSRF labs against cloud metadata endpoints (169.254.169.254) in a safe lab
  • Learn insecure deserialization in at least one language (Java/PHP/Python pickle)
  • Study XXE (XML External Entity) injection and file disclosure via XML parsers
  • Integrate a DAST scan into a simple CI pipeline (GitHub Actions) for hands-on DevSecOps exposure
OWASP ZAP SSRF XXE GitHub Actions

Task heading at the end of week: CI-Integrated DAST Pipeline

Wire an OWASP ZAP baseline scan into a GitHub Actions workflow that runs on every push to a sample vulnerable repo.

Week 7: API Security Deep Dive

  • Study OWASP API Security Top 10 and how it differs from the web Top 10
  • Practice testing REST APIs for BOLA (Broken Object Level Authorization)
  • Learn GraphQL-specific risks: introspection abuse, batching attacks, nested query DoS
  • Set up Postman/Insomnia for structured API testing workflows
  • Practice mass assignment vulnerabilities and excessive data exposure scenarios
  • Study API rate limiting, throttling, and resource exhaustion testing
  • Learn API gateway security concepts (auth at the edge, schema validation)
  • Complete crAPI (Completely Ridiculous API) vulnerable lab end-to-end
OWASP API Top 10 crAPI GraphQL Postman

Task heading at the end of week: API Pentest on crAPI

Fully test crAPI for BOLA, mass assignment, and excessive data exposure; document each with a Postman collection reproducing the exploit.

Week 8: Threat Modeling & Secure Design

  • Learn STRIDE threat modeling methodology with worked examples
  • Practice building a data-flow diagram (DFD) for a sample application architecture
  • Study secure SDLC integration points: design review, code review, security testing, release gates
  • Learn how to write security requirements/abuse-case stories for a sprint
  • Study common cryptographic misuse: weak hashing (MD5/SHA1 for passwords), ECB mode, hardcoded keys
  • Practice reviewing a real architecture diagram and identifying trust boundaries
  • Learn basics of secrets management (Vault, AWS Secrets Manager) vs hardcoded secrets
  • Write a one-page threat model for a project of your choice (e.g. your own portfolio site or VaultKeeper)
STRIDE DFD Secure SDLC Crypto Misuse

Task heading at the end of week: Threat Model Document

Produce a full STRIDE-based threat model with DFD for one of your own projects, listing top 5 threats and mitigations.

🚀 Milestone 2 Achievement

You can run and triage SAST/DAST tooling, test APIs against the OWASP API Top 10, and produce a professional threat model — the core toolkit of a working AppSec analyst.

Projects After Phase 2

Pick one to bridge into cloud/container and reporting-focused AppSec work.

DevSecOps Pipeline

Build a CI/CD pipeline combining SAST (Semgrep), SCA (Dependency-Check), and DAST (ZAP) with pass/fail gates.

Hint: Fail the build if critical-severity findings appear; document the gate logic.

API Security Test Suite

Write an automated Postman/Newman test suite that checks for BOLA and mass assignment on a sample API.

Hint: Parameterize user roles/tokens to test horizontal and vertical access in one run.

Secrets Leak Scanner

Build a script using gitleaks or trufflehog to scan repos for hardcoded secrets, with a custom report formatter.

Hint: Test it against your own old commits first — it's surprisingly common.

Threat Modeling Workshop Content

Turn your STRIDE learning into a teaching workshop/carousel explaining threat modeling to junior devs.

Hint: Use one relatable app example (e.g. a login system) throughout for consistency.

Phase 3: Cloud/Container AppSec, Reporting & Career Readiness

Days 61-90: Cloud-native security, professional reporting, and the certification/interview push

🎯 Phase 3 Goals

Container Security Cloud Misconfig Pentest Reporting CI/CD Security Interview Prep

Week 9: Container & Docker Security

  • Study Docker architecture risks: privileged containers, exposed daemon socket, image layers
  • Practice scanning images with Trivy and Grype for known CVEs
  • Learn Dockerfile security best practices (non-root users, minimal base images, multi-stage builds)
  • Study container escape concepts at a high level (for defensive awareness)
  • Practice hardening a sample Dockerfile and re-scanning to confirm reduced findings
  • Learn Kubernetes security basics: RBAC, network policies, pod security standards
  • Study supply chain security: SBOM generation with Syft, image signing concepts
  • Integrate Trivy into your earlier CI/CD pipeline as a container security gate
Trivy Docker Hardening Kubernetes RBAC SBOM

Task heading at the end of week: Hardened Container Pipeline

Take a deliberately insecure Dockerfile, scan it, fix every finding, and add Trivy as a CI gate that blocks high/critical CVEs.

Week 10: Cloud Security Fundamentals (AWS-Focused)

  • Study the AWS shared responsibility model and where AppSec fits in
  • Learn common S3 misconfigurations: public buckets, missing encryption, weak bucket policies
  • Practice using ScoutSuite or Prowler against a free-tier AWS lab account
  • Study IAM misconfiguration patterns: overly broad policies, privilege escalation paths
  • Learn cloud metadata service abuse (tying back to SSRF from Week 6)
  • Study Infrastructure-as-Code security: scanning Terraform with Checkov or tfsec
  • Practice fixing a deliberately vulnerable Terraform config and re-scanning
  • Document a personal cloud security misconfiguration checklist
AWS IAM Prowler Checkov Terraform

Task heading at the end of week: Cloud Misconfig Audit

Run Prowler against a free-tier AWS account, triage the top 10 findings, and write fixes including corrected IAM policy JSON.

Week 11: Professional Reporting & Communication

  • Study how real pentest/AppSec reports are structured: exec summary, scope, methodology, findings, appendix
  • Practice writing findings with clear business impact, not just technical detail
  • Learn CVSS v3.1 scoring in depth — calculate scores manually for past findings
  • Practice presenting a finding to a "non-technical stakeholder" in plain language (record yourself if possible)
  • Study how to track remediation: ticketing, re-test cycles, risk acceptance documentation
  • Learn the basics of compliance frameworks relevant to AppSec (PCI-DSS, SOC 2 touchpoints)
  • Compile your 90-day labs into a single portfolio-style master report
  • Get feedback on your report from a peer or community (Discord/LinkedIn group)
CVSS v3.1 Report Writing PCI-DSS Stakeholder Comms

Task heading at the end of week: Master Portfolio Report

Compile your strongest 5 findings across all 90 days into one polished, CVSS-scored report suitable for sharing with recruiters.

Week 12: Certification & Interview Readiness

  • Review and attempt practice questions aligned to a target cert (e.g. eWPT, CAP, or relevant CompTIA/Security+ AppSec objectives)
  • Do a full mock pentest under time pressure (pick any retired HTB/PortSwigger lab) and report within 4 hours
  • Prepare answers for common AppSec interview questions (explain XSS to a junior dev, walk through a code review, etc.)
  • Build a one-page resume bullet list translating your 90 days into measurable skills/achievements
  • Polish your GitHub: pin your best 3 projects (pipeline, threat model, master report) with clean READMEs
  • Practice a mock technical interview (explain a vulnerability chain end-to-end out loud)
  • Research target companies/roles and tailor your resume + LinkedIn headline accordingly
  • Plan your next 90 days: pick a specialization (cloud security, red teaming, or secure code review lead)
Mock Interviews Resume Building GitHub Portfolio Cert Prep

Task heading at the end of week: Job-Ready Portfolio Package

Finalize a GitHub portfolio, resume bullets, and one polished pentest report — your complete application package for AppSec Analyst roles.

🏆 Final Achievement

Congratulations! You now have a working AppSec toolkit (manual testing, SAST/DAST, API security, threat modeling, container/cloud security) plus a portfolio of real reports and a job-ready application package — the foundation of a genuinely employable Application Security Analyst.

What Next

Where to take your AppSec career after Day 90

1. Specialize

  • Pick one lane: cloud security, secure code review, or red teaming
  • Go deep on one cloud provider (AWS/Azure/GCP) security certification
  • Specialize in one tech stack (e.g. Java/Spring AppSec, or Node.js AppSec)
  • Consider a mobile AppSec track (Android/iOS) as a growth area
  • Explore DevSecOps engineering as a hybrid role
  • Look into security architecture as a longer-term path
  • Consider bug bounty hunting as a parallel income/skill track
  • Pursue an advanced cert aligned to your chosen lane
  • Join a specialized community for that niche
  • Set a 6-month deep-specialization goal

2. Apply & Network

  • Apply to entry-level AppSec Analyst / Junior Pentester roles weekly
  • Tailor your resume per job description using your portfolio reports
  • Attend local OWASP/BSides meetups and introduce yourself
  • Reach out to AppSec professionals on LinkedIn for informational chats
  • Ask for referrals once you've built real community connections
  • Keep your GitHub portfolio updated with new projects
  • Practice mock interviews monthly to stay sharp
  • Track applications and follow up professionally
  • Consider freelance/contract AppSec gigs to build experience
  • Set a weekly application/networking quota and stick to it

3. Keep Building

  • Stay current with weekly CVE/security news roundups
  • Do at least one CTF or lab per week to keep skills sharp
  • Re-test old projects with new tools/techniques quarterly
  • Write a monthly technical blog post about something you learned
  • Build a second, more advanced portfolio project every 90 days
  • Track and revisit OWASP Top 10 changes as they're updated
  • Mentor beginners — teaching reinforces your own mastery
  • Read one new security book per month
  • Attend at least one virtual conference talk per month
  • Reassess your roadmap every quarter and adjust goals

4. Give Back

  • Turn your 90-day notes into content for Virtual Mentors SOIT
  • Create a beginner-friendly AppSec series for your audience
  • Answer questions in community forums/Discords regularly
  • Open-source one of your lab setups or scripts for others to use
  • Host a free workshop/webinar on one AppSec topic
  • Write a "lessons learned" retrospective on your 90 days publicly
  • Pair up with another learner for accountability
  • Contribute documentation fixes to a tool you use often
  • Review and give feedback on a peer's pentest report
  • Pay it forward — share this exact roadmap with someone starting out
