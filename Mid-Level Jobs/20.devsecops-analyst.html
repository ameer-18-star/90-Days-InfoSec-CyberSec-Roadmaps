90-Day Roadmap For "DevSecOps Analyst" Mastery

An intermediate-track plan for learners who already know basic Linux, Git, and one programming language — and are ready to specialize in embedding security directly into CI/CD pipelines, infrastructure, and the software delivery lifecycle.

Phase 1: CI/CD Foundations & Shift-Left Security

Days 1-30: Pipeline mechanics, version control security, and your first automated security gate

🎯 Phase 1 Goals

CI/CD Pipelines Git Security Shift-Left Security SAST Integration Secrets Scanning

Week 1: CI/CD Pipeline Mechanics

  • Study how CI/CD pipelines actually work: triggers, stages, runners, artifacts, deployment targets
  • Set up GitHub Actions on a sample repo and build a basic build-test-deploy pipeline from scratch
  • Learn the difference between continuous integration, continuous delivery, and continuous deployment
  • Study pipeline-as-code concepts and why version-controlled pipelines matter for security and auditability
  • Learn how secrets/environment variables are handled in CI runners and where leaks commonly happen
  • Study runner security: self-hosted vs. GitHub-hosted, and the trust implications of each
  • Read one real-world CI/CD supply chain breach case study (e.g. SolarWinds/CodeCov) and map root cause
  • Document 15 DevSecOps terms in your own glossary (SAST, DAST, SCA, SBOM, shift-left, etc.)
GitHub Actions Pipeline-as-Code CI Runners Supply Chain

Task heading at the end of week: First Pipeline + Breach Case Study

Build a working build-test-deploy GitHub Actions pipeline for a sample app, and write a one-page breakdown of a real CI/CD supply chain breach and its root cause.

Week 2: Git & Source Control Security

  • Study branch protection rules: required reviews, status checks, signed commits
  • Learn how to enforce signed commits with GPG/SSH signing and why provenance matters
  • Practice setting up gitleaks/trufflehog as a pre-commit hook to stop secrets before they're pushed
  • Study .gitignore discipline and how to safely purge a secret that's already in commit history
  • Learn repository access control: least-privilege team permissions, CODEOWNERS files
  • Study dependency pinning and lockfiles as a defense against supply chain tampering
  • Practice configuring Dependabot/Renovate for automated dependency update PRs
  • Build a personal "secure repo setup checklist" you can apply to any new project
Branch Protection gitleaks CODEOWNERS Dependabot

Task heading at the end of week: Secure Repo Setup

Configure a sample repo with branch protection, a gitleaks pre-commit hook, CODEOWNERS, and Dependabot enabled; document each setting's purpose.

Week 3: SAST & Secrets Scanning in the Pipeline

  • Learn the shift-left principle: why catching issues at commit time beats catching them in production
  • Set up Semgrep as a CI step running on every pull request
  • Practice tuning Semgrep rules to reduce noise without missing real findings
  • Learn how to fail a build on critical-severity SAST findings while allowing warnings through
  • Study CodeQL as GitHub's native semantic code analysis option and how it differs from pattern-based SAST
  • Practice integrating gitleaks as a CI gate (not just a local pre-commit hook) for defense in depth
  • Learn how to triage SAST findings: true positive vs. false positive vs. accepted risk
  • Write a one-page "SAST findings triage" decision framework for your own future use
Semgrep CodeQL Shift-Left Build Gates

Task heading at the end of week: SAST-Gated Pipeline

Add Semgrep and gitleaks as required CI checks on a sample repo that block merges on critical findings; document your triage framework.

Week 4: Software Composition Analysis (SCA) & SBOM

  • Study why third-party dependencies are the largest attack surface in modern apps
  • Set up OWASP Dependency-Check or Snyk to scan a sample project's dependency tree
  • Learn what an SBOM (Software Bill of Materials) is and why it's increasingly required by regulation/customers
  • Practice generating an SBOM with Syft in CycloneDX and SPDX formats
  • Study transitive dependency risk and how a vulnerability 4 layers deep still affects you
  • Learn how license compliance scanning fits into SCA tooling (not just security, but legal risk)
  • Practice setting up a CI step that fails on critical CVEs in direct dependencies only (tuning severity vs. depth)
  • Document your own SCA tool comparison (Dependency-Check vs Snyk vs OWASP tools) based on hands-on use
SCA SBOM Syft CycloneDX

Task heading at the end of week: SCA + SBOM Pipeline Step

Add an SCA scan to your pipeline that generates a CycloneDX SBOM artifact on every build and fails on critical CVEs in direct dependencies.

🎯 Milestone 1 Achievement

You can build a CI/CD pipeline from scratch, secure source control with branch protection and secrets scanning, and gate builds on SAST and SCA findings — the foundational toolkit of a DevSecOps Analyst.

Projects After Phase 1

Pick one to consolidate pipeline security fundamentals before moving into deeper automation and infrastructure.

Hint: Use GitHub's "reusable workflows" feature so others can adopt it with minimal setup.

Git History Secret Purge Lab

Hint: Document every step — this is a real skill people panic about when it happens for real.

SBOM Comparison Report

Generate SBOMs for 3 different open-source projects and compare dependency risk profiles across them.

Hint: Look for projects with very different dependency tree sizes for a more interesting comparison.

Shift-Left Security Teaching Carousel

Turn your Phase 1 notes into a 10-part educational explainer series for your audience.

Hint: One concept per piece (SAST, SCA, SBOM, secrets scanning, etc.), beginner-friendly language.

Phase 2: DAST, IaC Security & Container Pipelines

Days 31-60: Extend automated security into runtime testing, infrastructure-as-code, and containerized deployments

🎯 Phase 2 Goals

DAST Automation IaC Security Container Pipelines Policy-as-Code Secrets Management

Week 5: DAST Automation in CI/CD

  • Study how DAST differs from SAST in a pipeline context: it needs a running application to test against
  • Set up OWASP ZAP in baseline scan mode against a sample app spun up inside the pipeline itself
  • Practice using Docker Compose in CI to stand up a full app stack for DAST testing before teardown
  • Learn how to handle authenticated DAST scans (session handling) in an automated, non-interactive way
  • Study how to tune DAST scan scope and duration to fit within CI time/cost budgets
  • Practice configuring ZAP automation framework YAML configs instead of manual GUI scans
  • Learn how to publish DAST results as a pipeline artifact and fail builds on high-severity findings
  • Document the tradeoffs between full DAST scans on every PR vs. scheduled nightly scans
OWASP ZAP Docker Compose ZAP Automation Framework Authenticated Scans

Task heading at the end of week: Ephemeral DAST Pipeline

Build a CI job that spins up a sample app via Docker Compose, runs an authenticated ZAP scan against it, publishes results, and tears the stack down.

Week 6: Infrastructure-as-Code (IaC) Security in Pipelines

  • Study why IaC scanning matters: catching misconfigurations before they're ever deployed, not after
  • Set up Checkov and tfsec as required pipeline steps scanning Terraform on every pull request
  • Practice fixing common Terraform findings: open security groups, unencrypted resources, public S3
  • Learn how to write custom Checkov rules for organization-specific policy requirements
  • Study policy-as-code with Open Policy Agent (OPA)/Conftest and how it generalizes beyond Terraform
  • Practice writing a Rego policy that enforces one specific organizational rule (e.g. mandatory tags)
  • Learn how Terraform plan output can be scanned pre-apply for a true "shift-left" IaC gate
  • Build a personal "IaC pipeline gate" reference architecture you can reuse across projects
Checkov tfsec OPA/Conftest Rego

Task heading at the end of week: Policy-as-Code IaC Gate

Add Checkov and one custom OPA/Rego policy as required pipeline checks on a Terraform repo, blocking merge on violations.

Week 7: Container Build & Deployment Pipelines

  • Study multi-stage Docker builds and how they reduce final image attack surface
  • Practice integrating Trivy as a CI step that scans images before they're pushed to a registry
  • Learn image signing concepts with Cosign/Sigstore and why provenance matters for deployed containers
  • Study admission controllers in Kubernetes that can block unsigned or unscanned images at deploy time
  • Practice setting up a registry-level scan gate (e.g. blocking push of images with critical CVEs)
  • Learn distroless/minimal base image strategies and how to migrate a Dockerfile to one
  • Study how to automate Dockerfile linting (hadolint) as an early pipeline check
  • Build a fully gated container pipeline: lint → build → scan → sign → deploy
Trivy Cosign/Sigstore hadolint Admission Controllers

Task heading at the end of week: Gated Container Pipeline

Build a full lint-build-scan-sign pipeline for a containerized app, where Trivy findings and missing signatures both block deployment.

Week 8: Secrets Management & Pipeline Identity

  • Learn why hardcoded pipeline secrets (API keys, cloud credentials) are a top breach vector
  • Study OIDC-based federated identity for pipelines (e.g. GitHub Actions to AWS, no long-lived keys)
  • Practice configuring a GitHub Actions workflow that assumes an AWS role via OIDC instead of static keys
  • Learn HashiCorp Vault or AWS Secrets Manager integration patterns for pipeline secret retrieval
  • Study secret scanning at the organization level (GitHub Advanced Security, GitGuardian) vs. per-repo tools
  • Practice rotating a pipeline secret and confirming zero downtime during the rotation
  • Learn how to scope pipeline permissions tightly (GITHUB_TOKEN permissions block) to limit blast radius
  • Document a "pipeline identity and secrets" reference guide for future projects
OIDC Federation Vault/Secrets Manager GITHUB_TOKEN Scoping Secret Rotation

Task heading at the end of week: Keyless Cloud Deployment

Reconfigure a pipeline that deploys to AWS to use OIDC federation instead of static access keys, eliminating long-lived credentials entirely.

🚀 Milestone 2 Achievement

You can automate DAST testing inside ephemeral environments, gate deployments on IaC and container security findings, and eliminate static secrets using federated identity — the practical toolkit that fills a DevSecOps Analyst's day-to-day work.

Phase 3: Observability, Compliance Automation & Career Readiness

Days 61-90: Security monitoring as code, compliance automation, and the certification/interview push

🎯 Phase 3 Goals

Security Observability Compliance-as-Code Incident Response Automation Metrics & Reporting Interview Readiness

Week 9: Security Observability & Monitoring as Code

  • Study how runtime security monitoring complements pipeline-time scanning (you can't catch everything pre-deploy)
  • Learn Falco basics for runtime container/Kubernetes anomaly detection
  • Practice writing a Falco rule that detects an unexpected shell spawned inside a container
  • Study how centralized logging (CloudTrail, application logs, audit logs) feeds security dashboards
  • Learn how to define and track DevSecOps-relevant metrics: mean time to remediate, scan coverage %, escaped defects
  • Practice building a simple security metrics dashboard from your own pipeline's historical scan data
  • Study how alert fatigue happens and how to tune detection rules to stay actionable
  • Document a "monitoring as code" config (Falco rules + alert routing) version-controlled alongside your app
Falco Monitoring as Code Security Metrics Alert Tuning

Task heading at the end of week: Runtime Detection Rule Set

Write 3 custom Falco rules detecting suspicious container behavior, version-controlled in your repo, with a short doc explaining each rule's intent.

Week 10: Compliance-as-Code & Automated Evidence

  • Study how compliance frameworks (SOC 2, ISO 27001, PCI-DSS) increasingly expect automated, continuous evidence
  • Learn how CSPM/pipeline scan results can be mapped automatically to compliance control IDs
  • Practice tagging your existing pipeline security gates with the compliance controls they satisfy
  • Study how GRC platforms (Vanta, Drata) pull automated evidence from CI/CD and cloud APIs
  • Learn the concept of "continuous compliance" vs. point-in-time audits, and why DevSecOps enables it
  • Practice writing a script that exports your pipeline's scan history as audit-ready evidence artifacts
  • Study how policy-as-code (from Week 6) doubles as both a security gate and compliance evidence
  • Document a control-to-pipeline-step mapping for 10 common compliance requirements
Compliance-as-Code Continuous Compliance Evidence Automation Control Mapping

Task heading at the end of week: Automated Evidence Export

Build a script that exports your pipeline's last 10 security scan results as timestamped, audit-ready evidence files mapped to specific compliance controls.

Week 11: Incident Response Automation & Resilience

  • Study how DevSecOps teams build automated rollback as a security control, not just a reliability one
  • Practice configuring a pipeline that automatically rolls back a deployment on a failed post-deploy health/security check
  • Learn how feature flags and canary deployments reduce blast radius when a security issue surfaces post-release
  • Study chatops patterns: routing pipeline security alerts directly into Slack/Teams with actionable context
  • Practice building a simple chatops integration that posts a formatted alert when a critical scan finding appears
  • Learn how blameless postmortems work and why they matter for sustainable security culture
  • Study how to write a postmortem for a pipeline security incident (e.g. a leaked secret that reached production)
  • Compile your 90-day labs into a single portfolio-style "DevSecOps maturity" writeup
Automated Rollback Canary Deployments ChatOps Postmortems

Task heading at the end of week: Self-Healing Pipeline + Postmortem

Add an automated rollback trigger to your pipeline on failed post-deploy checks, and write a blameless postmortem for a simulated leaked-secret incident.

Week 12: Certification & Interview Readiness

  • Review and attempt practice questions aligned to a target cert (e.g. Certified DevSecOps Professional, AWS Security Specialty, or CKS)
  • Do a full mock pipeline security build under time pressure: take an insecure sample repo and fully gate it within 4 hours
  • Prepare answers for common DevSecOps interview questions (explain shift-left, walk through a pipeline architecture, etc.)
  • Build a one-page resume bullet list translating your 90 days into measurable skills/achievements
  • Polish your GitHub: pin your best 3 projects (gated pipeline, policy-as-code library, evidence automation) with clean READMEs
  • Practice a mock technical interview (explain a full pipeline security architecture end-to-end out loud)
  • Research target companies/teams and tailor your resume + LinkedIn headline accordingly
  • Plan your next 90 days: pick a specialization (platform engineering, cloud security, or security automation lead)
Mock Interviews Resume Building GitHub Portfolio Cert Prep

Task heading at the end of week: Job-Ready DevSecOps Portfolio

Finalize a GitHub portfolio, resume bullets, and one polished "DevSecOps maturity" writeup — your complete application package for DevSecOps Analyst roles.

🏆 Final Achievement

Congratulations! You now have a working DevSecOps toolkit (CI/CD security gates, IaC and container pipelines, secrets federation, runtime observability, compliance automation) plus a portfolio of real pipelines and a job-ready application package — the foundation of a genuinely employable DevSecOps Analyst.

What Next

Where to take your DevSecOps career after Day 90

1. Specialize

  • Pick one lane: platform engineering, cloud security, or security automation/tooling
  • Go deep on Kubernetes-native security (CKS, Kyverno, OPA Gatekeeper)
  • Consider compliance automation as a specialized GRC-adjacent track
  • Explore site reliability engineering (SRE) as a related discipline worth understanding
  • Look into internal developer platform (IDP) engineering as a senior path
  • Consider a specific cloud provider's DevSecOps tooling as a deep specialization
  • Specialize in supply chain security (SLSA framework, Sigstore ecosystem)
  • Pursue an advanced cert aligned to your chosen lane
  • Join a specialized community for that niche
  • Set a 6-month deep-specialization goal

2. Apply & Network

  • Apply to entry-level DevSecOps Analyst / DevSecOps Engineer roles weekly
  • Tailor your resume per job description using your pipeline portfolio
  • Attend local DevSecOps Days/CNCF meetups and introduce yourself
  • Reach out to DevSecOps professionals on LinkedIn for informational chats
  • Ask for referrals once you've built real community connections
  • Keep your GitHub portfolio updated with new pipeline projects
  • Practice mock interviews monthly to stay sharp
  • Track applications and follow up professionally
  • Consider freelance/contract pipeline security audits to build experience
  • Set a weekly application/networking quota and stick to it

3. Keep Building

  • Stay current with weekly supply chain security advisories and CVE roundups
  • Do at least one new tool/lab per week to keep your pipeline skills sharp
  • Re-test old pipelines with new tools/techniques quarterly
  • Write a monthly technical blog post about something you learned
  • Build a second, more advanced portfolio project every 90 days
  • Track new releases in the CI/CD security tooling ecosystem
  • Mentor beginners — teaching reinforces your own mastery
  • Read one new DevSecOps/DevOps book per month
  • Attend at least one virtual conference talk per month
  • Reassess your roadmap every quarter and adjust goals

4. Give Back

  • Turn your 90-day notes into content for Virtual Mentors SOIT
  • Create a beginner-friendly DevSecOps series for your audience
  • Answer questions in community forums/Discords regularly
  • Open-source one of your pipeline templates or policy libraries for others to use
  • Host a free workshop/webinar on one DevSecOps topic
  • Write a "lessons learned" retrospective on your 90 days publicly
  • Pair up with another learner for accountability
  • Contribute documentation fixes to a tool you use often
  • Review and give feedback on a peer's pipeline security setup
  • Pay it forward — share this exact roadmap with someone starting out
